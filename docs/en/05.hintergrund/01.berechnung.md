### Where to take questions and bugs

1. From v0.7.0, first look at the "Problems" tab in the instance settings. It checks all sources and suggests a fix.
2. Read the [troubleshooting](../04.fehlerbehebung/README.md) pages.
3. Report a bug or a feature request as an issue in the [GitHub repository](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues). Check first whether there is already an issue for it. Include the versions of SourceAnalytix, js-controller and Node.js, and attach the log of the affected source.

## Why do the values differ from my meter, portal or evcc?

<!-- abschnitt: prio=B; gewicht=10; readme=missing; cluster=cumulative-power-05,prices-costs-18; features=source-power-integration,source-average-power,calc-consumption-formula,source-cumulative-meter -->
<!-- muss beantworten: Unterschiede durch Messzeitpunkt, Integration, Einheit und Startwerte. -->

**In short:** There are usually four possible reasons: the source is a power value in W that sends only rarely; a portal or wallbox assigns the consumption to a different point in time; the device measures differently from your meter; or the start values, unit or total don't fit. The table helps you find the cause.
<!-- quelle: forum=731502; forum=1348168; forum=1168164; forum=488316 -->

| Cause | How to recognize it | What helps |
|---|---|---|
| The source is a power value (W) that sends only every few minutes | The values differ a lot, often by a multiple | Use the device's total counter in kWh, or make the device send more often, for example every 10 seconds |
| A power source had a pause | After an outage, consumption is missing or far too high | See [Pauses](#sourceanalytix-convert-watts-kwh), from v0.7.0 "Maximum gap between power values (minutes)" |
| Different point in time for assigning the consumption | Daily values differ, but the sum over several days matches | Nothing, both values are right. Compare longer periods |
| The device measures differently from the grid operator's meter | Consumption and feed-in don't match the meter in the basement | Read the meter itself, for example with a reading head |
| Start values, unit or total are wrong | Values are negative, far too high or off by a fixed amount | See [Correct wrong values](../02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative) |
<!-- quelle: forum=572093; forum=488316; forum=731502; code=lib/calculation.js:766-787; issue=#1266; forum=1348168; forum=682759; forum=1168164; forum=528812 -->

### Power instead of a meter reading

From a power value, SourceAnalytix can only estimate the consumption. Each value applies until the next one. If a device sends only every 5 minutes, SourceAnalytix counts every short peak for the whole 5 minutes. If the device offers a meter reading in kWh, that is more accurate. For how the conversion works, see [How does SourceAnalytix convert watts to kWh?](#sourceanalytix-convert-watts-kwh).
<!-- quelle: code=lib/calculation.js:766-787; forum=572093; forum=488316 -->

### Different point in time for assigning the consumption

SourceAnalytix books consumption on the day it was measured: The daily value is the total now minus the total at 0:00. A wallbox or evcc, on the other hand, often books a whole charging session on the day it ends. Manufacturer portals sometimes work with 15-minute values. Over days or months, this evens out.
<!-- quelle: code=main.js:3722-3734; forum=1348168; forum=682759 -->

### The device measures differently

A Shelly 3EM counts consumption and feed-in per phase. The grid operator's meter offsets the phases against each other. With feed-in on one phase and consumption on another, the two therefore differ, even though SourceAnalytix calculates correctly.
<!-- quelle: forum=1168164 -->

## How does SourceAnalytix convert watts to kWh?

<!-- abschnitt: prio=B; gewicht=7; readme=missing; cluster=cumulative-power-04,prices-costs-27,cumulative-power-27; features=source-power-integration,source-average-power,output-timestamps-ack,source-cumulative-meter -->
<!-- muss beantworten: Riemann-Summe/Mittelwert, Update-getriebene Berechnung, Pausen. -->

**In short:** With every new power value, SourceAnalytix calculates the energy since the previous value: previous power × time since the previous value. This is a left Riemann sum. With "Average power values" it uses the average of the previous and the new value instead. The energy is converted to the target unit and added to the total.
<!-- quelle: code=lib/calculation.js:766-787; code=main.js:3862-3935; code=main.js:3488-3496; issue=#1166 -->

### The formula

Energy in Wh = power in W × time in hours. An example with three values:

| Time | Value | without averaging | with averaging |
|---|---|---|---|
| 10:00 | 0 W | Starting point | Starting point |
| 10:30 | 1,000 W | 0 W × 0.5 h = 0 Wh | 500 W × 0.5 h = 250 Wh |
| 11:00 | 1,000 W | 1,000 W × 0.5 h = 500 Wh | 1,000 W × 0.5 h = 500 Wh |
| Sum | | 500 Wh = 0.5 kWh | 750 Wh = 0.75 kWh |
<!-- quelle: code=lib/calculation.js:766-787 -->

Without averaging, the calculation suits devices that switch abruptly and send only when something changes. With averaging, it suits sensors whose power rises and falls smoothly and that send regularly.
<!-- quelle: code=admin/jsonCustom.json:107-117@v0.6.1; issue=#1166 -->

### It only calculates when a new value arrives

SourceAnalytix calculates as soon as the source writes a value, even if the value stays the same. What counts is the value's timestamp. A device that sends only when something changes is still calculated correctly: The last value applies until a new one arrives.
<!-- quelle: code=main.js:2527-2566; code=main.js:3879-3885; interview=9 -->

### Pauses

- **First value:** After activation, after a restart of SourceAnalytix and after a change of the settings, the first value is only the starting point. The energy of the pause before it is missing.
- **Long silence while the instance is running:** If no new value arrives for a long time, SourceAnalytix extends the last value over the whole pause. **From v0.7.0**, "Maximum gap between power values (minutes)" limits this. Longer pauses then count as 0 ([#1266](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1266)).
- **Midnight:** **From v0.6.2**, SourceAnalytix books the energy up to 0:00 to the old day and carries on with the same value in the new day. A value that is older than the previous day is not extrapolated ([#1254](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/1254)).
- **Negative values:** With "Ignore negative values" they count as 0 W.
<!-- quelle: code=main.js:2194-2198; code=main.js:3925-3932; code=main.js:3898-3908; code=main.js:3086-3125; code=main.js:2789-2793; code=lib/calculation.js:752-755; issue=#1254; issue=#1266 -->

Power sources have no reset detection and no start values to enter. Their total starts at 0 on activation.
<!-- quelle: code=main.js:3031@v0.6.1; code=src-admin/src/Wizard.tsx:709-725; code=main.js:1910-1911@v0.6.1 -->

## How is consumption calculated, and why is currentYear lower than my meter reading?

<!-- abschnitt: prio=B; gewicht=1; readme=covered; cluster=meter-readings-05; features=calc-consumption-formula,output-cumulative-reading,source-start-values -->
<!-- muss beantworten: Formel Verbrauch = Zählerstand minus Startwert. -->

**In short:** This is by design. `currentYear.consumed.05_currentYear` is this year's consumption, not the meter reading: total minus the "Year" start value. You find the meter reading itself in `sourceanalytix.0.<device>.cumulativeReading`.
<!-- quelle: code=main.js:3722-3734; issue=#641 -->

The same formula applies to every period: consumption = total − start value of the period. The start value is the total at the beginning of the period. SourceAnalytix sets it itself at every period rollover, for example on 1 January at 0:00 for "Year".
<!-- quelle: code=main.js:3722-3734; code=main.js:2780-2786 -->

| | Value |
|---|---|
| Total (`cumulativeReading`) | 12,480 kWh |
| "Year" start value (total on 1 January) | 11,900 kWh |
| `05_currentYear` | 580 kWh |
<!-- quelle: code=main.js:3722-3734 -->

If you only activated SourceAnalytix during the year, the "Year" start value is the total at the time of activation. The year then counts from that day. If you want it to count from 1 January, enter the meter reading from 1 January as the start value, see [What do I enter for the start values (and in which unit)?](../01.erste-schritte/02.erster-zaehler.md#start-values-unit).
<!-- quelle: code=lib/calculation.js:365-384; code=lib/calculation.js:199-221@v0.6.1 -->

SourceAnalytix stores the meter reading at the end of each period under `currentYear.meterReadings` if "Store meter readings" is on.
<!-- quelle: code=main.js:2605-2607 -->

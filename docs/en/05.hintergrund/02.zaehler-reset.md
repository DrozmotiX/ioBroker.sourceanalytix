## What does "Device reset detected" mean and how does reset detection work?

<!-- abschnitt: prio=A; gewicht=23; readme=partial; cluster=meter-readings-09,cumulative-power-16,meter-readings-10; features=source-reset-detection,reset-confirmation,reset-jitter-ignore,source-threshold,source-hidden-reset-keys -->
<!-- muss beantworten: Schwellwert, Bestätigung, Überlauf, Stromausfall. -->

It's a warning, not an error. The source's meter reading dropped clearly, for example after a restart, power failure, overflow or meter swap, and SourceAnalytix keeps counting on top of the previous total. No negative values are created.
<!-- quelle: code=main.js; code=lib/calculation.js; forum=561385 -->

### The terms

| Term | Meaning |
|---|---|
| Target unit | the unit of the price definition that everything is calculated in |
| Device value | the source datapoint's value in the target unit; can drop back |
| Total | `cumulativeReading`, SourceAnalytix's own meter reading; with reset detection it never drops |
| Offset | total = device value + offset; shown on the source under "For experts" as `valueAtDeviceReset` |
| Start value | the total at the start of a period; consumption = total − start value |
| Threshold | the largest drop that still counts as measurement jitter, default 1 |
<!-- quelle: code=main.js; code=lib/calculation.js; code=src-admin/src/SourceDetail.tsx -->

### How it works

1. **Equal or higher:** the value is taken over.
2. **Lower, up to the threshold:** measurement jitter, the value is ignored.
3. **Clearly lower:** a possible reset. SourceAnalytix keeps the total and waits for the next value ("Waiting for another reading …").
4. **The next value decides:** if it is close to the old reading again, it was an outlier ("Rejected a possible device reset"). If it stays low, the reset is confirmed ("Device reset detected …") and the offset is set anew. If the old reading comes back in one step after a confirmed reset, SourceAnalytix undoes the reset ("Rolled back the device reset …").
<!-- quelle: code=lib/calculation.js; code=main.js; issue=#1199; issue=#1258 -->

Example with a threshold of 1 kWh, meter at 1,000 kWh, at 0 after a power failure:

| Device value | Offset | Total |
|---|---|---|
| 1,000 kWh | 0 | 1,000 kWh |
| 0 kWh | 0 | 1,000 kWh (waiting) |
| 0.4 kWh | 1,000 | 1,000.4 kWh |
<!-- quelle: code=lib/calculation.js -->

Only what the device counted between its last value before the reset and the first one after it is lost. If SourceAnalytix was stopped during the reset, it detects it with the first value after the start, as long as the device hasn't overtaken the old reading yet. Power sources have no reset detection.
<!-- quelle: code=lib/calculation.js; code=main.js; interview=4; forum=897463 -->

Without reset detection, SourceAnalytix takes over every drop, and the total and periods drop with it. This is only meant for sources that are allowed to drop.
<!-- quelle: code=lib/calculation.js; code=main.js; issue=#1262 -->

## Counter that is reset to 0 every day: what happens internally?

<!-- abschnitt: prio=B; gewicht=16; readme=partial; cluster=cumulative-power-15,periods-07,meter-readings-27,upgrade-migration-other-29; features=source-cumulative-meter,reset-confirmation,source-power-integration,source-reset-detection,source-threshold -->
<!-- muss beantworten: Tageszähler (z. B. Ertrag heute), Mitternacht, Abzug am Folgetag. -->

With reset detection, the nightly drop to 0 is an ordinary reset: the total keeps going, and only a small remainder is lost each night. Without reset detection, the total drops, and the previous day's consumption is subtracted again.
<!-- quelle: code=lib/calculation.js; code=main.js; interview=4; forum=948910 -->

Example with a threshold of 0.1 kWh, daily counter at 4.2 kWh in the evening:

| Time | Device value | Total | What happens |
|---|---|---|---|
| 23:58 | 4.2 kWh | 1,004.2 kWh | – |
| 0:00 | – | 1,004.2 kWh | period rollover, the new day starts at 0 |
| 0:01 | 0 kWh | 1,004.2 kWh | waiting |
| 0:10 | 0.05 kWh | 1,004.25 kWh | reset confirmed, today 0.05 kWh |
<!-- quelle: code=lib/calculation.js; code=main.js -->

It doesn't matter whether the device drops back shortly before or after midnight. If the threshold is larger than the daily consumption, the drop counts as jitter, and the start of the new day is lost. The wizard marks daily counters as "daily counter"; if possible, use the device's total counter.

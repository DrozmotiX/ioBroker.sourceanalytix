## Where do I find yesterday, last week, last month (previous states)?

<!-- abschnitt: prio=A; gewicht=25; readme=partial; cluster=periods-13,periods-14; features=current-year-previous,output-basic-period-states,rollover-previous-timestamps,output-cost-vs-earnings,rollover-midnight-cron,output-tree-layout,output-cumulative-reading,output-statistics-json,output-info-price-states,output-state-deletion,output-timestamps-ack -->
<!-- muss beantworten: previous*-States, Zeitstempel, wann sie gefüllt werden; Kosten/Einnahmen. -->

In the source's detail view under "Values", as "Yesterday", "Last week", "Last month", "Last quarter" and "Last year". As states they are under `sourceanalytix.0.<device>.currentYear.<category>` in `01_previousDay` to `05_previousYear`.
<!-- quelle: code=src-admin/src/SourceDetail.tsx; code=src-admin/src/i18n/en.json; code=main.js; issue=#137; forum=217254; forum=224702 -->

| Folder under `currentYear` | Content | Present when |
|---|---|---|
| `consumed` / `delivered` | consumption / feed-in | "Consumption" is on |
| `costs` / `earnings` | costs / earnings | "Costs" is on |
| `meterReadings` | meter reading at the end of the period | "Store meter readings" is on |
<!-- quelle: code=main.js -->

They are filled at the period rollover at 0:00: `01_previousDay` after the first midnight, `02_previousWeek` on the first Monday, `03_previousMonth` on the first of the month. Until then they hold 0. The timestamp is 23:59:59 on the last day of the period, so the value lands on the right day in the history.
<!-- quelle: code=main.js; code=lib/calculation.js; forum=635881; forum=660342; issue=#463; issue=#497 -->

With "Weekday", the days of last week are listed individually under `previousWeek.01_Monday` to `07_Sunday`. The states only exist if "Previous period" is on under "Main settings" (the default).
<!-- quelle: code=main.js; code=admin/jsonConfig.json; code=io-package.json -->

Consumption across midnight is split between both days by time, even if ioBroker or the device was off during the night. If an outage lasts several days, the days in between get no values of their own.
<!-- quelle: issue=#1260; issue=#1254; interview=11a; code=main.js -->

**See also:** [Week, month and quarter states](#week-month-quarter-states-weekdays) · [Catching up the day rollover](../02.anleitungen/05.betrieb-und-wartung.md#iobroker-was-down-midnight-recover)

## Which week, month and quarter states and weekdays are there?

<!-- abschnitt: prio=B; gewicht=16; readme=partial; cluster=periods-21,periods-25; features=current-year-weekday,current-year-weeks,current-year-months,current-year-quarters,year-statistics-archive,rollover-midnight-cron,rollover-missed-recovery-start,rollover-hourly-safety-check,rollover-recover-periods-button,rollover-sendto-recoverperiods,rollover-previous-timestamps,rollover-year-change,rollover-weekday-reset -->
<!-- muss beantworten: State-Baum des laufenden Jahres, Wochentage Mo-So, letzte 7 Tage. -->

Depending on the options under "Main settings" › "Current year", the values of every weekday, calendar week, month and quarter of the current year. Rolling values such as "the last 7 days" don't exist.
<!-- quelle: code=lib/calculation.js; code=admin/jsonConfig.json; code=main.js -->

```text
sourceanalytix.0.<device>
├── cumulativeReading
├── statisticsJson
└── currentYear
    └── <category>
        ├── 01_currentDay … 05_currentYear
        ├── 01_previousDay … 05_previousYear
        ├── currentWeek.01_Monday … 07_Sunday
        ├── previousWeek.01_Monday … 07_Sunday
        ├── weeks.01 … 53
        ├── months.01_January … 12_December
        └── quarters.Q1 … Q4
```
<!-- quelle: code=main.js; code=lib/calculation.js -->

| States | Option | Starts over |
|---|---|---|
| `currentWeek.<day>` | "Weekday" | on Mondays |
| `weeks.01` to `53` (ISO calendar week) | "Weeks" | on 1 January |
| `months.01_January` to `12_December` | "Months" | on 1 January |
| `quarters.Q1` to `Q4` | "Quarters" | on 1 January |
<!-- quelle: code=lib/calculation.js; code=main.js; code=admin/i18n/en.json -->

There are no `current` states under `meterReadings`; the current reading is in `cumulativeReading`. Build the last 7 days from `currentWeek` and `previousWeek`. To keep values beyond the year, use "Year statistics", see [Turn of the year](#happens-turn-year).
<!-- quelle: code=main.js; interview=Funktionswünsche; issue=#424 -->

**See also:** [Instance settings](01.einstellungen.md#instance-settings-exist-periods-decimals) · [Week 52/53 in the new year](../05.hintergrund/03.perioden-und-zeit.md#week-52-53-have-values)

<a id="json-values-vis"></a>

## Is there a JSON with all values (for VIS)?

<!-- abschnitt: prio=B; gewicht=9; readme=covered; cluster=outputs-viz-19,prices-costs-23; features=output-statistics-json,output-basic-period-states,output-cost-vs-earnings,output-tree-layout -->
<!-- muss beantworten: Aufbau von statistics-JSON und Tabelle. -->

Yes, `sourceanalytix.0.<device>.statisticsJson`. It contains all values of the current year: running periods, previous periods, weekdays, weeks, months and quarters, each for consumption, costs and meter readings.
<!-- quelle: code=main.js; code=lib/statistics-json.js -->

```json
{
  "schemaVersion": 1,
  "year": 2026,
  "source": { "id": "<datapoint ID>", "name": "House power", "unit": "kWh" },
  "quantity": {
    "type": "consumed",
    "current": { "day": 4.2, "week": 31.7, "month": 120.4, "quarter": 410.9, "year": 2950.3 },
    "previous": { "day": 5.1, "week": 33.2, "month": 140.8, "quarter": 420.5, "year": 3510.6 },
    "periods": {
      "weekdays": { "1": 5.3, "2": 4.2 },
      "previousWeekdays": { "1": 4.9, "2": 5.0, "3": 4.4, "4": 4.6, "5": 4.8, "6": 5.2, "7": 4.3 },
      "weeks": { "45": 33.2, "46": 31.7 },
      "months": { "10": 140.8, "11": 120.4 },
      "quarters": { "3": 420.5, "4": 410.9 }
    }
  },
  "financial": { "type": "costs", "currency": "€", "current": {}, "previous": {}, "periods": {} },
  "meterReadings": { "current": 48213.4, "previous": {}, "periods": {} }
}
```
<!-- quelle: code=lib/statistics-json.js -->

| Field | Content |
|---|---|
| `quantity` | consumption (`consumed`) or feed-in (`delivered`); `null` without "Consumption" |
| `financial` | costs (`costs`) or earnings (`earnings`) with `currency`; `null` without "Costs" |
| `meterReadings` | meter readings, `current` = `cumulativeReading`; `null` without "Store meter readings" |
| `periods.weekdays` | `1` (Monday) to `7` (Sunday) |
| `periods.weeks`, `months`, `quarters` | calendar week, month, quarter as the key |
<!-- quelle: code=lib/statistics-json.js; code=main.js -->

If an option is off, its group is `null`. The year archive is not in the JSON. In a script, read it with `JSON.parse(getState('sourceanalytix.0.<device>.statisticsJson').val)`.
<!-- quelle: code=lib/statistics-json.js; code=main.js -->

**See also:** [Values in VIS and Flot](../02.anleitungen/04.werte-auswerten.md#visualise-values-vis-flot-habpanel)

<a id="happens-turn-year"></a>

## What happens at the turn of the year?

<!-- abschnitt: prio=B; gewicht=8; readme=partial; cluster=periods-20; features=year-statistics-archive,rollover-year-change,current-year-previous,price-scheduled-valid-from -->
<!-- muss beantworten: Vorjahreswerte, neue Ordner, Jahresarchiv. -->

On 1 January at 0:00, the year value moves to `05_previousYear`, all running periods start at 0, and `weeks`, `months` and `quarters` under `currentYear` are cleared. `cumulativeReading` keeps going.
<!-- quelle: code=main.js; code=lib/calculation.js -->

With "Year statistics", SourceAnalytix creates the folder `sourceanalytix.0.<device>.<year>` for the new year, with weeks, months or quarters and the year totals `consumedCumulative`, `costsCumulative` and `readingCumulative`. Folders of past years stay unchanged and may be deleted.
<!-- quelle: code=main.js; interview=8 -->

> [!WARNING]
> Without "Year statistics", the old year's month, week and quarter values are afterwards only in a history adapter. By default "Months" is on, "Weeks" and "Quarters" are off.
<!-- quelle: code=main.js; code=io-package.json -->

A price with "Valid from" 1 January applies from 0:00, and the basic fee is booked as on every first of the month. The days at the end of December that belong to calendar week 01 land in the new year's week archive.
<!-- quelle: code=lib/dynamic-pricing.js; code=lib/calculation.js; code=main.js; issue=#1259; issue=#1256 -->

**See also:** [Evaluating across several years](../02.anleitungen/04.werte-auswerten.md#evaluate-across-years-adjusting-everything) · [Cleaning up old years](../02.anleitungen/05.betrieb-und-wartung.md#restart-datapoint-clean-up-old)

## How can I read and set prices as states?

<!-- abschnitt: prio=B; gewicht=6; readme=covered; cluster=prices-costs-03; features=price-current-price-writable,price-history-states,output-info-price-states -->
<!-- muss beantworten: Preis-States, Historie, info-Preis-States. -->

Under `sourceanalytix.0.priceDefinitions.<category>`. `currentPrice` is writable: a new value applies immediately to all sources of this price definition.
<!-- quelle: code=main.js -->

| State | Content | Writable |
|---|---|---|
| `priceDefinitions.<category>.currentPrice` | the price that applies right now | yes |
| `priceDefinitions.<category>.configuredPrice` / `configuredPriceValidFrom` | "Price per unit" and its "Valid from" | no |
| `priceDefinitions.<category>.configuredBasicPrice` / `configuredBasicPriceValidFrom` | "Price per month" and its "Valid from" | no |
| `priceHistory.<category>` | price history as JSON, `[{"ts":…,"price":0.32}]` | no |
| `basicPriceHistory.<category>` | history of the basic fee | no |
<!-- quelle: code=main.js; code=lib/dynamic-pricing.js -->

In the IDs, every character except letters, digits, `_` and `-` becomes `_`: `House power` becomes `House_power`. A written price applies from now and does not change costs already booked. With "Datapoint" or "Tariff selector", the next value of the price state overwrites it.
<!-- quelle: code=main.js; code=lib/dynamic-pricing.js -->

```javascript
setState('sourceanalytix.0.priceDefinitions.Power.currentPrice', 0.29);
```

**See also:** [Price definition](01.einstellungen.md#price-definition-structured-categories-base) · [Dynamic electricity price](../02.anleitungen/03.preise-und-kosten.md#use-dynamic-electricity-price-tibber)

<a id="meter-readings-cumulative"></a>

## Why are meter readings cumulative?

<!-- abschnitt: prio=B; gewicht=3; readme=partial; cluster=periods-30; features=output-cumulative-reading,current-year-previous,output-tree-layout -->
<!-- muss beantworten: Meter-Readings-Ordner und cumulativeReading erklärt. -->

Because they hold meter readings, not consumption. Each state shows the total at the end of its period, so it grows from month to month. Consumption is under `consumed`.
<!-- quelle: code=main.js -->

| State | Content |
|---|---|
| `cumulativeReading` | SourceAnalytix's total, unrounded, written with every value |
| `currentYear.meterReadings.months.<month>` etc. | the total at the end of that period |
| `currentYear.meterReadings.01_previousDay` etc. | the total at the period rollover |
<!-- quelle: code=main.js -->

Example: February 1,250 kWh, March 1,480 kWh, so about 230 kWh in March. The total includes the offset from reset detection and therefore doesn't follow the value the device currently reports. To make it match the real meter, use [Align meter reading](../02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative).
<!-- quelle: code=main.js; code=lib/calculation.js; issue=#640 -->

**See also:** [Why is currentYear lower than my meter reading?](../05.hintergrund/01.berechnung.md#consumption-calculated-currentyear-lower-than)

<a id="currency-sourceanalytix-use"></a>

## Which currency does SourceAnalytix use?

<!-- abschnitt: prio=B; gewicht=2; readme=missing; cluster=prices-costs-11; features=calc-currency -->
<!-- muss beantworten: Währung der Kosten und Grenzen (nur eine Währung). -->

The one from the ioBroker system settings, otherwise `€`. There is one currency for all sources, and SourceAnalytix doesn't convert. Enter all prices in this currency per unit, so €/kWh, not cents/kWh. After changing the currency, restart the instance.
<!-- quelle: code=main.js; code=lib/dynamic-pricing.js -->

<a id="sendto-commands-info-states"></a>

## sendTo commands and info states

<!-- abschnitt: prio=B; gewicht=0; readme=missing; cluster=; features=msg-getpricedefinitions,msg-getunits,msg-getusedoutputids,msg-recoverperiods,info-recoverperiods-state,info-no-connection-state -->
<!-- muss beantworten: recoverPeriods, info-States, fehlende info.connection. -->

The settings page controls SourceAnalytix through `sendTo` commands, which you can also call from scripts. Values are in the unit of the price definition, `source` is the ID of the source datapoint, and `dryRun: true` only returns a preview.
<!-- quelle: code=main.js -->

| Command | Parameters | Effect |
|---|---|---|
| `recoverPeriods` | `source` (optional) | catch up missed period rollovers |
| `getSources` / `checkProblems` | – | sources, problems, prices, units, currency |
| `saveSource` | `source`, `settings`, `dryRun` | create or change settings; known fields only |
| `setSourceEnabled` | `source`, `enabled` | resume or pause a source; data stays |
| `findCandidates` | `query` | search for matching datapoints |
| `setCumulative` | `source`, `value`, `dryRun` | "Align meter reading" |
| `meterSwap` | `source`, `oldEnd`, `newStart`, `date`, `dryRun` | "Meter swapped" |
| `recalcCosts` | `source` or `priceDefinition`, `from`, `dryRun` | "Recalculate costs from date" |
| `deleteSourceData` | `source` or `outputId`, `dryRun` | "Delete data"; source folders only |
| `getUsedOutputIds` | – | all technical IDs with their source datapoint |
<!-- quelle: code=main.js; code=lib/source-actions.js; issue=#1305; issue=#1306 -->

```javascript
sendTo('sourceanalytix.0', 'setCumulative', { source: '<datapoint ID>', value: 12475, dryRun: true }, result => {
    log(JSON.stringify(result));
});
```

Every command gets an answer. On failure it contains `error` and `message`, for example `sourceNotActive`, `invalidValue`, `invalidSettings` or `unknownCommand`.
<!-- quelle: code=main.js; code=lib/source-actions.js; issue=#1305 -->

> [!CAUTION]
> `deleteSourceData` without `dryRun` permanently deletes the source's folder with all years and its settings.
<!-- quelle: code=main.js -->

| info state | Content |
|---|---|
| `info.recoverPeriods` | button: `true` catches up missed rollovers of all sources |
| `info.costRecalculation` | progress of "Recalculate costs from date" as JSON |
<!-- quelle: code=main.js -->

There is no `info.connection` state, because SourceAnalytix has no device connection.
<!-- quelle: code=io-package.json -->

<a id="log-warnings-output-id-prices"></a>

## Log warnings (output ID, prices)

<!-- abschnitt: prio=B; gewicht=0; readme=missing; cluster=; features=log-startup-summary,log-source-config-errors,log-lifecycle-info,log-output-id,log-price-warnings,log-calculation-errors,log-reset-messages,log-rollover-messages,log-first-activation,log-sentry-error-handling -->
<!-- muss beantworten: Liste der Log-Meldungen mit Bedeutung. -->

These are the most important messages, so you can recognise them. For everyday operation, the log level "warn" is enough. The "Problems" tab shows most problems more clearly.
<!-- quelle: code=main.js; interview=5 -->

### Start and setup

| Message | Meaning |
|---|---|
| `Partially activated SourceAnalytix for <n> of <m> states …` | some sources are not running; the cause is logged before it |
| `Initialization of <datapoint> failed …` | this source does not start, see [Initialization failed](../04.fehlerbehebung/01.log-meldungen.md#messages-initialization-failed-cannot-handle) |
| `No unit defined for <datapoint> …` | unit missing, see [No unit defined](../04.fehlerbehebung/01.log-meldungen.md#error-unit-not-supported-no) |
| `Unit <a> of <datapoint> cannot be converted to unit <b> …` | the unit doesn't match the price definition |
| `The data of <datapoint> is stored in <a>, but price definition <name> uses <b> …` | the price definition uses another unit than the stored data |
| `No cost type defined …` / `Selected Type <name> does not exist …` | no or a deleted price definition |
| `Price definition <n> has no category …` / `Price definition <name> is ignored …` | category empty or used twice |
| `Start value <period> … is larger than the current total …` | start value too large, the period turns negative |
| `The basic fee of price definition <name> is included by <n> sources …` | the basic fee counts several times |
<!-- quelle: code=main.js; issue=#1264; issue=#1268; issue=#1310 -->

### Prices

| Message | Meaning |
|---|---|
| `Price definition <name> has no valid unit price …, using 0 …` | the price is not a number, costs stay 0 |
| `Price source state <state> … has no valid value …` | the price state is empty, "Price per unit" applies |
| `Unit price for <name> changed from <old> to <new>` | the price has changed |
<!-- quelle: code=main.js; issue=#1259 -->

### Calculation, reset and period rollover

| Message | Meaning |
|---|---|
| `Value … of <datapoint> is not a number, reading ignored` | text instead of a number |
| `Waiting for another reading before confirming a possible device reset …` | possible reset, waiting for the next value |
| `Device reset detected for <datapoint>; preserving cumulative value …` | reset confirmed, the total keeps going |
| `Rejected a possible device reset …` / `Rolled back the device reset …` | the low value was an outlier |
| `No new power value from <datapoint> for <n> min …` | a power gap is not counted |
| `Processing calendar rollover for <datapoint> …` | period rollover processed |
<!-- quelle: code=main.js; issue=#1257; issue=#1258; issue=#1260; issue=#1266 -->

### Output ID

| Message | Meaning |
|---|---|
| `Migrated SourceAnalytix output for <datapoint> from <old> to <new>` | technical ID changed, folder moved |
| `Cannot use output ID "<ID>" for <datapoint>: <reason>; keeping "<old>"` | the new ID is invalid or already taken |
<!-- quelle: code=main.js -->

Code errors start with `[<function>] error:` and include the stack. If the Sentry plugin is active, they are also sent to the developer.
<!-- quelle: code=main.js; issue=#1261 -->

<a id="migrating-older-versions-legacy-settings"></a>

## Migrating from older versions and legacy settings

<!-- abschnitt: prio=B; gewicht=0; readme=missing; cluster=; features=migration-output-id-change,migration-output-id-recovery,migration-output-id-default,migration-rounding-per-source,migration-legacy-cumulative-states,migration-dynamic-cost-v2,migration-legacy-native-keys -->
<!-- muss beantworten: Output-ID-Migration, unterbrochene Migration, alte native Schlüssel. -->

SourceAnalytix takes over data from older versions on start by itself; you don't have to do anything. Folders, total and decimals stay as they were. If moving a technical ID is interrupted, SourceAnalytix repeats it on the next start.
<!-- quelle: code=main.js; code=lib/output-id.js; code=io-package.json -->

The instance data still contains old keys such as `store_days`, `keep_months`, `impuls` or `status_logging`. They have no effect. Options from old forum posts such as "Number of days" no longer exist.
<!-- quelle: code=io-package.json; code=admin/jsonConfig.json; issue=#1263 -->

## Other (unfinished/internal functions)

<!-- abschnitt: prio=B; gewicht=0; readme=missing; cluster=; features=other-sentry-plugin,other-impulse-counter-unfinished,other-vis-widget-json-unfinished,other-cleanup-unused-unfinished,other-period-placeholder-unfinished,other-object-subscription,other-console-debug -->
<!-- muss beantworten: VIS-Widget-JSON, Debug-Ausgabe. -->

There is no separate widget JSON for VIS; use [`statisticsJson`](#json-values-vis). On start, SourceAnalytix writes units and prices with `console.debug` to the process's standard output, for example the Docker log, not to the ioBroker log. SourceAnalytix watches all objects so it notices changes to sources without a restart.

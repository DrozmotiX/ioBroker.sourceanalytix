## Values or costs far too high or negative – is the unit right?

<!-- abschnitt: prio=B; gewicht=12; readme=covered; cluster=prices-costs-17,setup-ui-19,periods-19; features=unit-detection-conversion,source-unit,source-start-values,supported-units,price-definitions-table -->
<!-- muss beantworten: Einheit und Startwerte prüfen, Jahresordner fehlt wegen Einheit. -->

**In short:** Usually a unit doesn't match. The source has a different unit selected than the device delivers, the price isn't given per unit of the price definition, or a start value was entered in the wrong unit. Check these places in the source detail, then correct the values.
<!-- quelle: code=main.js:2072-2090; code=lib/calculation.js:202-231; forum=562155; forum=1097521; forum=600948; forum=823571 -->

### The most common causes

| What is wrong | What you see | Correct |
|---|---|---|
| Source unit is `kWh`, but the device delivers `Wh` | All values are 1,000 times too high | The unit the device delivers |
| Power and energy mixed up, for example `kW` instead of `kWh` | A meter reading is summed up over time like a power value, and the values grow far too fast | Meter reading with an energy unit (`kWh`), power with `W` or `kW` |
| "Price per unit" in cents instead of euros, for example `28.5` instead of `0.285` | Costs 100 times too high | Price per unit of the price definition, so per kWh or per m³ |
| Start value in `Wh`, but the price definition calculates in `kWh` | Consumption strongly negative | Start value in the target unit |
<!-- quelle: code=lib/calculation.js:42-65@v0.6.1; code=main.js:3446-3471; code=lib/calculation.js:766-781; code=admin/i18n/de.json:55; forum=1239306; forum=486811; forum=549375; forum=796798 -->

The terms target unit, total and start value are explained under [The terms](../05.hintergrund/02.zaehler-reset.md#device-reset-detected-mean-reset).

### How to check it (from v0.7.0)

1. Under "Instances", open the settings of the SourceAnalytix instance and, on the "Overview" tab, your source.
2. Read "Type" at the top: it says, for example, "Meter reading · kWh" or "Power · W → kWh". That is the measurement type and the target unit. Compare the "Total" with your meter.
3. Under "Settings", check the "Unit" field. It must be the unit the device delivers. After the "Price definition", its unit is shown in brackets.
4. On the "Price definitions" tab, check the "Price per unit" of the selected category.
5. Look at the "Problems" tab. A start value that doesn't fit appears there as "Start value does not fit".
<!-- quelle: code=src-admin/src/SourceDetail.tsx:263-278; code=src-admin/src/SourceDetail.tsx:388-422; code=src-admin/src/i18n/de.json:140; code=src-admin/src/i18n/de.json:143; code=src-admin/src/i18n/de.json:211; code=lib/source-overview.js:166-168; code=admin/jsonConfig.json:38-43 -->

From v0.7.0, SourceAnalytix checks start values as you enter them. If a start value only fits when divided by 1000, the field asks "Looks like Wh – did you mean … ?". For more, see [What do I enter for the start values (and in which unit)?](../01.erste-schritte/02.erster-zaehler.md#start-values-unit).
<!-- quelle: code=lib/source-overview.js:106-110; code=src-admin/src/api.ts:267; code=src-admin/src/i18n/de.json:85; issue=#1267 -->

### Repairing values

If you change the unit, SourceAnalytix doesn't correct values that are already written. Afterwards, bring the total in line with your meter using the "Align meter reading" action, and recalculate the costs with "Recalculate costs from date". For how to repair consumption in running and completed periods, see [Correcting wrong values](../02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative).
<!-- quelle: code=lib/source-actions.js:33-45; code=lib/source-actions.js:235-243; issue=#640; issue=#947; forum=562155 -->

### No folder is created at all, not even a year folder

If SourceAnalytix doesn't recognise the unit at all, it doesn't start the source and creates no states, so no year folder either. This is described under [Error "unit not supported" / "No unit defined"](01.log-meldungen.md#error-unit-not-supported-no).
<!-- quelle: code=main.js:2087-2089; code=main.js:2134-2140; forum=925303 -->

## After an update or restore, values are 0 or SourceAnalytix is missing

<!-- abschnitt: prio=B; gewicht=7; readme=missing; cluster=upgrade-migration-other-02,upgrade-migration-other-03; features=source-hidden-reset-keys,reset-manual-correction,migration-legacy-cumulative-states -->
<!-- muss beantworten: Nach Restore Pakete neu installieren; Roh-Schlüssel prüfen. -->

**In short:** After a restore, the adapter itself is often missing, because a backup saves settings and data, not the program code. In that case, reinstall SourceAnalytix from the "latest" repository. If values are 0 afterwards, or the total doesn't match your meter, align it from v0.7.0 with "Align meter reading".
<!-- quelle: forum=1352377; forum=1329319; forum=1172189; interview=21; issue=#640 -->

### SourceAnalytix is missing after the restore

If the restore reports "Unknown packetName", for example, or the instance doesn't start, the adapter isn't installed. SourceAnalytix is only available in the "latest" (beta) repository. Switch the repository and install SourceAnalytix as described under [How do I update SourceAnalytix (and what is a downgrade)?](../02.anleitungen/05.betrieb-und-wartung.md#update-sourceanalytix-downgrade). The restored instance with its data then keeps running.
<!-- quelle: forum=1352377; forum=1329319; forum=1172189; interview=21 -->

### Values 0 or errors after an update or restore

An update doesn't change your values. After a restore, however, the total in the `cumulativeReading` state and the offset in the datapoint's settings can come from different points in time. The total then no longer matches the meter.
<!-- quelle: code=main.js:2121-2131; forum=587649; forum=914227 -->

How to check it (from v0.7.0):

1. In the instance settings, open the source on the "Overview" tab and compare the "Total" with your meter. You'll find the offset under "For experts" as `valueAtDeviceReset`.
2. If the total is wrong, choose "Align meter reading" under "Actions" and enter the reading your meter shows.
3. Look at the "Problems" tab. You recover a "Period rollover missed" with "Recover".
<!-- quelle: code=src-admin/src/SourceDetail.tsx:275-278; code=src-admin/src/SourceDetail.tsx:289-306; code=src-admin/src/SourceDetail.tsx:602-611; code=lib/source-overview.js:172-174; code=src-admin/src/i18n/de.json:209; issue=#640; issue=#1269 -->

**Up to v0.6.1**, a source doesn't start if the offset is larger than the total. The log then shows "Check settings for … Known valueAtDeviceReset …". From v0.6.2, it keeps running. For what to do then, see [Error "Known valueAtDeviceReset > known cumulative value"](01.log-meldungen.md#error-known-valueatdevicereset-known-cumulative).
<!-- quelle: code=main.js:1943-1952@v0.6.1; issue=#1257 -->

**Up to v0.6.x:** You can only see the offset in the datapoint's object under `common.custom.sourceanalytix.0` as `valueAtDeviceReset`. For how to set it and the total to matching values by hand, see [Correcting wrong values](../02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative).
<!-- quelle: code=main.js:1904-1912@v0.6.1; interview=1 -->

> [!TIP]
> If you move to a new system, take a full backup and don't restore it around midnight. That keeps the total and the settings together.
<!-- quelle: interview=11c -->

**See also:** [Where is the data, how do I back it up and how do I move it?](../02.anleitungen/05.betrieb-und-wartung.md#data-back-up-move-new) · [ioBroker was off over midnight](../02.anleitungen/05.betrieb-und-wartung.md#iobroker-was-down-midnight-recover)

<a id="costs-stay-0-not-calculated"></a>

## Costs stay 0 or are not calculated

<!-- abschnitt: prio=B; gewicht=6; readme=partial; cluster=prices-costs-16; features=source-calc-costs,price-invalid-unit-price,source-price-definition,output-cost-vs-earnings,source-unit -->
<!-- muss beantworten: Preis, Einheit, Costs-Haken. -->

**In short:** Costs only appear if "Costs" is ticked for the source and the price definition has a valid "Price per unit". Also check the "Cost Type" of the price definition: for "Earnings", the values are under `earnings`, not under `costs`.
<!-- quelle: code=main.js:2160-2165; code=main.js:2601-2622; code=main.js:1455; forum=847112; forum=931989; issue=#750 -->

### Checklist (from v0.7.0)

1. **Is "Costs" ticked?** Open the source and check the "Costs" box under "Settings". Without it, SourceAnalytix doesn't create a `costs` or `earnings` folder. Change it, then click "Apply".
2. **Is a price definition selected, and does it fit?** If it's missing or its unit doesn't match, the source appears on the "Problems" tab (see [Error "No cost type defined"](01.log-meldungen.md#error-no-cost-type-defined)).
3. **Is the price valid?** On the "Price definitions" tab, check the "Price per unit". If it isn't a number, SourceAnalytix calculates with 0 and writes `Price definition <name> has no valid unit price <value>, using 0 to avoid invalid cost calculations` to the log.
4. **Is the price taken from a state?** If the state doesn't deliver a valid price, SourceAnalytix uses the fallback price you entered: `Price source state <state> for <name> has no valid value or tariff, using configured fallback price <price>`. If that is empty, the costs are 0.
5. **Costs or earnings?** With the "Cost Type" "Earnings" (feed-in), the values are under `sourceanalytix.0.<device>.currentYear.earnings` and the consumption under `currentYear.delivered`. In the source detail, the columns are called "Delivery" and "Earnings".
<!-- quelle: code=src-admin/src/SourceDetail.tsx:84-91; code=src-admin/src/i18n/de.json:125; code=main.js:2601-2622; code=main.js:1445-1456; code=admin/i18n/de.json:15; code=admin/i18n/de.json:23; code=admin/i18n/de.json:55; code=main.js:2164-2165; code=src-admin/src/SourceDetail.tsx:335-341; code=src-admin/src/i18n/de.json:80; code=src-admin/src/i18n/de.json:82 -->

For costs, you don't need "Store meter readings".
<!-- quelle: forum=1124421 -->

If you've corrected the price or the tick, "Recalculate costs from date" on the source recalculates the costs from a date onward using the price history. The consumption stays the same.
<!-- quelle: code=src-admin/src/i18n/de.json:14-16; issue=#947 -->

**Up to v0.6.x:** The box is called "Calculate costs" in the dialog at the datapoint. Since v0.5.0, missing or invalid prices no longer lead to invalid costs, but to 0 with a warning.
<!-- quelle: code=admin/jsonCustom.json:37-137@v0.6.1; code=CHANGELOG_OLD.md:20; issue=#750 -->

**See also:** [Assigning prices and creating your own tariffs](../02.anleitungen/03.preise-und-kosten.md#assign-prices-create-custom-tariffs) · [Are calculated costs recalculated when I change the price, and how do I change it from a certain date?](../02.anleitungen/03.preise-und-kosten.md#costs-recalculated-change-price-change) · [Recording PV yield and feed-in](../02.anleitungen/01.quellen-und-einheiten.md#track-pv-yield-feed-earnings)

<a id="huge-consumption-after-power-outage"></a>

## Huge consumption on power sources after a power outage

<!-- abschnitt: prio=B; gewicht=4; readme=missing; cluster=cumulative-power-07; features=source-power-integration,calc-calc-block -->
<!-- muss beantworten: Lücken und letzte Leistung; Abhilfe. -->

**In short:** With a power source, the last value applies until a new one arrives. If the device or the network goes down without reporting 0 first, SourceAnalytix extrapolates the last power over the whole gap. From v0.7.0, the "Maximum gap between power values (minutes)" setting prevents this.
<!-- quelle: code=lib/calculation.js:766-781; code=main.js:3862-3930; issue=#1266; forum=511607; forum=404253 -->

### Why this happens

SourceAnalytix multiplies each power value by the time until the next value. Up to v0.6.x, there is no upper limit for this. If no value arrived for three hours, three hours count at the last power. If SourceAnalytix itself was stopped, however, the first value after startup is just the new starting point, and the gap doesn't count at all.
<!-- quelle: code=lib/calculation.js:766-781; code=main.js:2194-2198; code=main.js:3889-3930; interview=9 -->

### How to prevent it (from v0.7.0)

1. In the SourceAnalytix instance settings, open the power source on the "Overview" tab.
2. In the "Settings" section, enter a value for "Maximum gap between power values (minutes)" that is clearly larger than the longest normal interval between two values from your device.
3. Click "⚡ Apply". A longer stretch without a value then counts as 0. The log shows `No new power value from <datapoint> for <n> min, longer than the maximum gap of <m> min; this interval is not counted`.
<!-- quelle: code=src-admin/src/SourceDetail.tsx:461-472; code=src-admin/src/SourceDetail.tsx:586-596; code=src-admin/src/i18n/de.json:155-156; code=main.js:3898-3912; issue=#1266; issue=#1285 -->

> [!WARNING]
> Leave the setting empty or at 0 if your device only sends when something changes. Otherwise, the consumption of long stretches at constant power is missing, for example a heater that runs for hours at the same power.
<!-- quelle: code=admin/i18n/de.json:137; interview=9 -->

If a power source doesn't deliver a value for three hours, then from v0.7.0 it appears on the "Problems" tab with "Power source has not reported for a long time".
<!-- quelle: code=lib/source-overview.js:136; code=lib/source-overview.js:169-171; code=src-admin/src/i18n/de.json:206 -->

**Up to v0.6.x:** Make sure the device reports 0 when it's switched off, or use a meter reading (kWh) instead of the power if the device has one (see [Which datapoint do I activate: meter (kWh) or power (W)?](../01.erste-schritte/02.erster-zaehler.md#datapoint-enable-meter-kwh-power)).
<!-- quelle: forum=511607; forum=404253 -->

You repair values that are already booked as described under [Correcting wrong values](../02.anleitungen/02.zaehlerstaende-korrigieren.md#correct-wrong-too-high-negative).

**See also:** [How does SourceAnalytix convert watts to kWh?](../05.hintergrund/01.berechnung.md#sourceanalytix-convert-watts-kwh)

## Why so many decimal places?

<!-- abschnitt: prio=B; gewicht=3; readme=partial; cluster=prices-costs-13; features=calc-rounding,rounding-instance-defaults,source-decimals -->
<!-- muss beantworten: Rundung und Standardwerte. -->

**In short:** By default, SourceAnalytix rounds consumption to 3 and costs to 2 decimal places. Each source has its own setting. From v0.7.0, you change it in the source detail under "For experts". With `-1`, SourceAnalytix stores the value without rounding, which gives many decimal places.
<!-- quelle: code=admin/jsonConfig.json:305-327; code=lib/calculation.js:283-290; code=main.js:1932-1935; code=src-admin/src/SourceDetail.tsx:514-543 -->

### Where to set the rounding

| Where | Fields | Applies to |
|---|---|---|
| Instance settings, "Main settings", "Rounding" section | "Decimals for consumption values" (default 3), "Decimals for cost values" (default 2) | only sources that are newly set up |
| Source detail, "Settings", "For experts" (from v0.7.0) | "Decimals for consumption", "Decimals for costs" | this source, after "Apply" |
<!-- quelle: code=admin/jsonConfig.json:295-327; code=admin/i18n/de.json:124-127; code=main.js:1932-1935; code=src-admin/src/SourceDetail.tsx:514-543; code=src-admin/src/i18n/de.json:68-69 -->

Existing sources keep their rounding, even if you change the instance default. Since v0.6.0, each source stores its own value.
<!-- quelle: code=admin/i18n/de.json:127; code=README.md:87 -->

### Why does it show 402.400?

SourceAnalytix writes a number, for example `402.4`. How many digits, zeros or thousands separators you see is determined by the display, so VIS, Admin or your visualisation.
<!-- quelle: code=lib/calculation.js:283-290; forum=786213 -->

**Up to v0.5.4:** The number of decimal places can't be set. From v0.5.5, you can set it for the instance and per source ([#934](https://github.com/DrozmotiX/ioBroker.sourceanalytix/issues/934)).
<!-- quelle: code=README.md:97; issue=#934 -->

**See also:** [Which instance settings are there (periods, decimals)?](../03.referenz/01.einstellungen.md#instance-settings-exist-periods-decimals)
